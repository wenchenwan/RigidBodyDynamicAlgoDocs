# 第 4 章 刚体系统建模 (Modelling Rigid Body Systems)

> **一句话概括**：把一个真实机构变成算法能吃的数据结构——
> 连通图 → 生成树 → parent array $\lambda(i)$ + 关节模型 `jcalc` + 惯性参数。

## 本章定位

这是**从物理到代码的桥梁**。第 5–7 章的所有算法都是在这一章定义的数据结构上跑的，
所以这章的每一个记号后面都会反复出现。**要实现算法的话，这章必须完整读。**

## 前置依赖

- 第 2 章（空间向量、坐标变换 $X$）
- 第 3 章（运动子空间 $S$）
- 图论常识：图、树、生成树、深度优先

## 核心概念

### 4.1 连通图 (Connectivity Graph)

把机械系统画成一个图：

- **节点 = 刚体 (body)**，含一个特殊节点 **body 0 = 固定基座 (fixed base)**
- **边 = 关节 (joint)**

**分类**：

| 图的性质 | 系统类型 | 处理章节 |
|---|---|---|
| 树（无回路） | 运动学树 (kinematic tree) | 第 5–7 章 |
| 含回路 | 闭环系统 (closed-loop system) | 第 8 章 |
| 无 body 0 连接 | 浮动基系统 (floating base) | 第 9 章 |

**重要事实**：$N_B$ 个刚体的树形系统恰有 $N_B$ 个关节（含连到基座的那个）。
含回路的系统关节数更多，多出来的边就是**闭环关节 (loop joint)**。

### 4.2 生成树与 parent array

对树形系统，选定 body 0 为根，则每个 body $i$ 有唯一的父节点：

$$
\lambda(i) = \text{body } i \text{ 的父节点编号}
$$

**正则编号规则 (regular numbering)** —— 全书最关键的约定之一：

$$
\boxed{\ \lambda(i) < i\quad \text{对所有 } i = 1,\dots,N_B\ }
$$

即**父节点编号一定小于子节点编号**（深度优先或广度优先遍历赋号即可满足）。

**为什么这条约定这么重要**：它让所有递推变成简单的**顺序 for 循环**，
不需要显式的树遍历或递归：

- `for i = 1 to N`：**外推 (outward)**，从根到叶——处理 $i$ 时父节点已算完 ✅
- `for i = N to 1`：**内推 (inward)**，从叶到根——处理 $i$ 时子节点已算完 ✅

这就是为什么 RNEA / CRBA / ABA 的伪代码全是平铺直叙的两三个 for 循环，
没有一行递归。**一个数组下标的约定，换来了全书算法形式上的极简。**

### 4.3 树上的几个集合

| 记号 | 名称 | 定义 | 用途 |
|---|---|---|---|
| $\lambda(i)$ | parent | $i$ 的父节点 | 所有递推 |
| $\mu(i)$ | children | $i$ 的直接子节点集合 | 内推的分支处理 |
| $\nu(i)$ | subtree | 以 $i$ 为根的子树（含 $i$） | 复合刚体惯性的范围 |
| $\kappa(i)$ | support | 从 $i$ 到根路径上的所有关节 | $H$ 的稀疏结构、Jacobian |
| $\mathrm{anc}(i)$ | ancestors | $i$ 的所有祖先 | 同上 |

**核心结论**（第 6 章要用）：

$$
H_{ij}\ne 0 \iff i\in\nu(j)\ \text{或}\ j\in\nu(i)
$$

即**只有存在祖先-后代关系的两个关节之间才有惯性耦合**。
人形机器人左臂和右臂之间的 $H$ 块恒为零——这不是近似，是精确的结构性零。

### 4.4 坐标系的放置与关节变换的拆分

每个 body $i$ 关联一个坐标系。从父到子的变换被**拆成两半**：

$$
{}^{i}X_{\lambda(i)} = X_{J}(i)\ X_{T}(i)
$$

| 变换 | 名称 | 依赖 | 含义 |
|---|---|---|---|
| $X_{T}(i)$ | 树变换 (tree transform) | **常量** | 从 $\lambda(i)$ 坐标系到关节 $i$ 的"预继" (predecessor) 坐标系，描述**连杆几何** |
| $X_{J}(i)$ | 关节变换 (joint transform) | $q_i$ | 从预继坐标系到 body $i$ 坐标系，描述**关节当前位形** |

**为什么要拆**：
- $X_T$ 是机器人的**固定几何参数**，建模时确定一次，运行时不变 → 可预计算
- $X_J$ 每步都随 $q$ 变，但形式极简单（例如转动关节就是一个绕轴旋转）
- 拆开后，换关节类型不影响连杆几何，换连杆几何不影响关节代码——**关注点分离**

> 这一拆分和 DH 参数法的目的类似，但更通用：DH 要求坐标系按特定规则放置，
> 本书的 $X_T$ 是任意的 6D 变换，可以处理 DH 无法表达的结构（如球关节、分支）。

### 4.5 关节模型与 `jcalc`

**关节模型 (joint model)** 是本书的核心抽象。给定关节类型和 $q_i,\dot q_i$，
函数 `jcalc` 返回三样东西：

```
[X_J, S, c_J] = jcalc(jtype(i), q_i, q̇_i)
```

| 输出 | 含义 | 备注 |
|---|---|---|
| $X_{J}$ | 关节变换（依赖 $q_i$） | $6\times6$（实现上用 $(E,r)$） |
| $S$ | 运动子空间矩阵 | $6\times n_i$，**常见关节在关节坐标系中是常量** |
| $\mathbf{c}_{J}$ | 关节偏置加速度 | $= \dot S\,\dot q$，**$S$ 为常量时恒为 0** |

**关节速度**：$\mathbf{v}_{J} = S\,\dot q_i$

> 💡 **实现提示**：对转动、移动、螺旋这些最常用的关节，$S$ 是常数向量、
> $\mathbf{c}_J = 0$。很多库直接对这几类关节做模板特化，跳过 $\mathbf{c}_J$ 的计算。
> 只有球关节等 $S$ 随 $q$ 变的类型才需要真的算 $\mathbf{c}_J$。

**标准关节类型**：

| 类型 | 英文 | $n_i$ | 关节坐标系中的 $S$（绕/沿 $z$ 轴） |
|---|---|---|---|
| 转动 | revolute | 1 | $[0\ 0\ 1\ 0\ 0\ 0]^{\mathsf T}$ |
| 移动 | prismatic | 1 | $[0\ 0\ 0\ 0\ 0\ 1]^{\mathsf T}$ |
| 螺旋 | helical / screw | 1 | $[0\ 0\ 1\ 0\ 0\ h]^{\mathsf T}$（$h$ = 螺距） |
| 圆柱 | cylindrical | 2 | 上面两列合起来 |
| 平面 | planar | 3 | 面内 2 平移 + 1 转动 |
| 球 | spherical | 3 | 3 个转动方向；$S$ 随姿态变 |
| 自由 | free / floating | 6 | $\mathbf{1}_{6}$ |
| 固定 | fixed | 0 | 空矩阵 |

⚠️ **球关节与自由关节的坑**：3 个或 6 个自由度的姿态不能用 3 个欧拉角无奇异地表示。
实践中用**四元数**表示位形 $q$，但用**角速度**表示 $\dot q$，
于是 $\dim q \ne \dim\dot q$（例如自由关节 $q$ 有 7 个数、$\dot q$ 有 6 个）。
这会打破"$q$ 和 $\dot q$ 维数相同"的朴素假设，实现时要小心区分**位形维数**和**自由度**。

### 4.6 系统模型的数据结构

一个完整的树形系统模型 = 以下几组数据：

```
model = {
    NB        : 刚体数目
    jtype[i]  : 关节 i 的类型                    i = 1..NB
    parent[i] : λ(i)，父节点编号，满足 λ(i) < i
    Xtree[i]  : X_T(i)，常量树变换
    I[i]      : body i 的空间惯性（在 body i 坐标系中表示，因而是常量）
    gravity   : 重力加速度向量（第 5 章的"重力技巧"要用）
}
```

**要点**：
- $I_i$ 存在 **body $i$ 自己的坐标系**里，所以是**常量**，可以预计算一次。
  这是"每个刚体带一个自己的坐标系"这个设计的最大好处。
- 整个模型只有 `parent` 数组编码了拓扑，**换拓扑只要换这一个数组**。

对应 `spatial_v2` 的 `model` 结构体（字段名 `model.NB`、`model.parent`、
`model.jtype`、`model.Xtree`、`model.I`）。〔待核对〕字段名以你的版本为准。

### 4.7 浮动基座 (Floating Base)

移动机器人（人形、四足、飞行器、航天器）的基座不固定。处理方法**极其简单**：

> 在 body 0（惯性系）和 base body 之间插入一个 **6-DoF 自由关节**。

于是浮动基系统在形式上仍然是一棵树，所有算法**原封不动可用**。
$n = 6 + (\text{关节自由度数})$，前 6 个"关节力"恒为零（没有东西驱动基座）。

第 9 章会讨论由此带来的特殊问题（前 6 行的 $\tau=0$ 约束、动量守恒等）。

### 4.8 闭环系统的建模（引入）

含回路的系统处理流程：

1. 在连通图上选一棵**生成树 (spanning tree)**；
2. 树上的关节照常处理；
3. 剩下的边成为**闭环关节 (loop joint)**，每条边给出一组**闭环约束方程**。

于是"闭环系统 = 树形系统 + 若干约束"，第 5–7 章的算法可以复用，
只需再加一层约束求解。第 8 章展开。

## 易错点与陷阱

1. **忘记检查 $\lambda(i)<i$**。自己造模型或从 URDF 导入时如果编号乱了，
   for 循环递推会读到未初始化的值，而且**不会报错**，只会算出错误结果。
   建议在加载模型时加一个断言。
2. **$X_T$ 和 $X_J$ 搞反顺序**。是 ${}^{i}X_{\lambda(i)} = X_J X_T$，
   先做树变换再做关节变换。反了会得到看似合理但完全错误的结果。
3. **$I_i$ 存错坐标系**。必须存在 body $i$ 自己的坐标系里（这样才是常量）。
   如果从 URDF 导入，注意 URDF 的 `<inertial><origin>` 表示的是
   质心坐标系相对连杆坐标系的偏移，需要做一次 $X^*IX$ 变换。
4. **球/自由关节的 $\dim q \ne \dim\dot q$**（见 4.5）。
5. **$S$ 的坐标系**。表里的 $S$ 都是在**关节坐标系**中的。
   用到别的坐标系时必须变换：${}^{A}S = {}^{A}X_{J}\,S$。
